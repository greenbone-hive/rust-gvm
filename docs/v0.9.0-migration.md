# Migrating from v0.8.0 to v0.9.0

`v0.9.0` adds an explicit SSH session/exec transport topology and tightens
resource and deadline behavior in the connection and mock-server crates. The
project remains a pre-1.0 Technology Preview, so the minor-version change is
the compatibility signal.

Most v0.8 callers can upgrade without changing existing calls. Direct
stream-local SSH remains the default, and the new mock-server limits are above
normal test workloads. Callers with exhaustive error matches, slow streaming
responses, incomplete mock requests, or non-loopback standalone listeners
should account for the changes below.

## SSH session/exec channels

`gvm-connection` exports `SshChannelMode`. Existing construction through
`SshConnection::new` still opens `direct-streamlocal@openssh.com` to
`SshConfig::remote_socket`. Opt into a standard SSH session plus exec request
with `with_channel_mode`:

```rust,no_run
use gvm_connection::{SshChannelMode, SshConfig, SshConnection};

let connection = SshConnection::new(SshConfig::default()).with_channel_mode(
    SshChannelMode::Exec {
        command: String::new(),
    },
);
```

An empty command is the compatibility mode used by current GOS tooling with a
server-side forced command. Non-empty commands are passed to the SSH server
unchanged. Debug output redacts command contents. `connect()` succeeds only
after the server acknowledges the exec request; rejection, early close, and
timeout leave the connection disconnected and reusable for a later attempt.

## Complete-response deadlines

`UnixSocketConfig::timeout`, `TlsConfig::timeout`, and `SshConfig::timeout` now
bound the complete response-read operation. In v0.8, each successful partial
read restarted the timeout, so a peer could keep a request alive indefinitely
by sending bytes frequently enough.

Increase the configured timeout if a legitimate gvmd response can take longer
than the current value from its first byte through complete XML framing. A
timeout still invalidates the connection and parser state; reconnect before
issuing another request.

## Typed-response nesting limit

Typed GMP response decoding rejects XML deeper than 256 elements and returns:

```rust
# use gvm_gmp::responses::ParseError;
# let error = ParseError::NestingLimitExceeded { max_depth: 256 };
match error {
    ParseError::NestingLimitExceeded { max_depth } => {
        eprintln!("response exceeded {max_depth} XML levels");
    }
    other => eprintln!("response error: {other}"),
}
```

`ParseError` is not non-exhaustive, so exhaustive v0.8 matches must add this
variant. Documents at exactly 256 levels remain accepted.

## Mock-server resource limits

All TCP, Unix, TLS, and SSH GMP sessions share a default concurrency limit of
64. Incomplete XML requests have one 30-second deadline starting with the first
byte; later chunks do not extend it. Shutdown cancels and drains active session
tasks, and stateful authentication is removed when its transport session ends.

Embedded users can override the defaults:

```rust,no_run
use gvm_mock_server::MockGmpServerBuilder;
use std::time::Duration;

let builder = MockGmpServerBuilder::new()
    .with_max_sessions(128)
    .with_request_timeout(Duration::from_secs(90));
```

The exported `DEFAULT_MAX_SESSIONS` and `DEFAULT_REQUEST_TIMEOUT` constants
allow wrappers to preserve repository defaults. `active_session_count()` and
`authenticated_session_count()` expose lifecycle state for deterministic
tests.

The standalone binary adds `--max-sessions` and
`--request-timeout-seconds`. TCP or TLS addresses outside loopback now also
require `--allow-non-loopback`; loopback and Unix-socket defaults are unchanged.

## Mock compatibility correction

The stateful mock server now returns `OK, request submitted` for a successful
`start_task`, matching gvmd. Update snapshots or exact status-text assertions
that expected the shorter `OK` string.

## Supported toolchain and artifacts

The minimum supported Rust version remains 1.89. Tagged release artifacts keep
the v0.8 publication contract: five mock-server binary archives with checksums,
a Linux amd64/arm64 GHCR index, CycloneDX SBOMs and quality results, and
Sigstore provenance attestations. Only immutable `v`-prefixed tags are
published; there is no moving `latest` image.
