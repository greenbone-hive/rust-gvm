# Migrating from v0.9.0 to v0.10.0

`v0.10.0` adds exact-byte streaming for explicitly opted-in GMP responses and
the first native report-page streaming model. It also adds typed semantic views
for server errors and feed synchronization state. The project remains a
pre-1.0 Technology Preview, so the minor-version change is the compatibility
signal.

Buffered `execute`, `send`, and `call` behavior remains available. Most callers
that do not use `GmpRequestError` as a `Copy` value can upgrade without changing
existing calls. Applications that stream report XML should adopt the explicit
completion and connection-lifecycle rules below.

## Capability-gated exact-byte streaming

`GmpClient::execute_stream` is available on Unix, TLS, and SSH transports that
implement `GvmStreamingConnection`. A request compiles with this operation only
when its associated response implements `GmpStreamingResponse`; ordinary
buffered response types do not become streamable through command-name checks.

The returned `GmpResponseStream` mutably borrows the connection and reads only
when the caller requests the next chunk. It yields the exact received bytes,
validates one complete XML frame, and returns `GmpStreamCompletion` containing
the observed `u64` byte count plus small response-specific metadata.

Use `execute_stream_with` when one operation needs explicit limits:

```rust,ignore
use std::time::Duration;

use gvm_client::StreamOptions;

let stream = client
    .execute_stream_with(
        request,
        StreamOptions {
            max_bytes: Some(512 * 1024 * 1024),
            max_retained_bytes: 4 * 1024 * 1024,
            idle_timeout: Some(Duration::from_secs(30)),
            total_timeout: Some(Duration::from_secs(300)),
        },
    )
    .await?;
let completion = stream.copy_to(&mut destination).await?;
```

`max_bytes` limits the complete streamed frame independently of the
connection's buffered-response ceiling. `max_retained_bytes` bounds an
unfinished root or XML token; the read that completes the root can make the
first yielded chunk larger by up to one bounded transport read. The idle
timeout covers each server read, while the optional total timeout includes
caller pauses and sink work.

`copy_to` writes every chunk with `write_all`, but does not flush, synchronize,
or close the caller-owned sink. Durable callers should write to a temporary
file, wait for successful completion, explicitly flush and `sync_all`, and then
atomically publish the file.

## Stream completion and connection reuse

Call `finish` to drain and validate bytes that the application no longer needs,
or `copy_to` to consume the full response into an async sink. The connection is
reusable only after the XML frame and response-specific completion metadata
both validate.

The connection is invalidated after a transport failure, timeout, premature
EOF, malformed or oversized XML, non-success GMP root status, decoder failure,
sink write failure, or an incomplete stream being dropped. Dropping a stream
never starts hidden background draining. Reconnect before the next request
after invalidation.

Raw streamed response chunks are not passed to the wire trace. A fixed marker
is emitted after successful validation so large or secret-bearing bodies are
not buffered or logged.

## Native report-page acquisition

`GetNativeReportPageRequest` is the first production request whose response
opts into generic streaming. It requires a report ID, a caller-owned result
filter, an explicit 1-based `first`, positive `rows`, and named output options:

```rust,ignore
use gvm_gmp::commands::reports::{
    GetNativeReportPageRequest, NativeReportPageOptions,
};

let request = GetNativeReportPageRequest::new(
    report_id,
    "severity>5 sort-reverse=severity",
    1,
    500,
    NativeReportPageOptions {
        lean: true,
        ..NativeReportPageOptions::default()
    },
)?;
let completion = client
    .execute_stream(request)
    .await?
    .copy_to(&mut native_xml)
    .await?;
```

The request always uses `details=1` and `ignore_pagination=0`. It rejects
`first` or `rows` in the caller's result filter, including grouped, spaced, and
case-varied forms, because the typed request owns those terms. An empty filter
explicitly selects all results in the supplied window.

`completion.metadata` is a `NativeReportPageResponse`. It excludes the large
report body but records available report and task IDs, scan status, resolved
filter data, the returned window, direct result count, result totals, and outer
report counts. Buffered `execute` also returns only this metadata and discards
the native XML bytes; use `execute_stream` when the original body is required.

## Safe page continuation

gvmd can return fewer results than requested because its **Max Rows Per Page**
setting is an upper bound. The response's `page.max` describes the returned
window and is not the number of direct result elements present.

After a successfully completed page:

1. Stop when `returned_results` is zero.
2. Otherwise compute the next `first` with checked signed arithmetic as
   `page.start + returned_results`.
3. When `result_count.filtered` is present, stop once the next `first` is
   greater than that count; otherwise continue until a zero-result page.

Do not advance by the requested `rows` or by `page.max`; either can skip data
when the server caps a page. A missing or unrepresentable `page.start`, overflow,
or inconsistent count metadata means automatic continuation is unsafe.

Pagination is not a snapshot. Prefer completed, immutable reports for
correctness-sensitive multi-page acquisition because results and tied sort
positions can change between requests.

## Request-error ownership

`GmpRequestError` now includes `FilterFragment`, whose source retains the exact
reserved pagination term rejected from a caller-authored filter. Consequently
the enum remains `Clone` but is no longer `Copy`.

Code that reused an error after moving it should borrow or clone explicitly:

```rust,ignore
fn record_request_error(error: &gvm_gmp::GmpRequestError) {
    tracing::warn!(%error, "invalid GMP request");
}

record_request_error(&error);
return Err(error);
```

Because the enum is non-exhaustive, downstream matches should already include a
wildcard arm. Code that listed known variants while using a wildcard can add a
specific `FilterFragment` arm when it needs the structured source.

## Semantic GMP server errors

`GmpServerErrorKind` provides one protocol-native classification for typed
parser errors and high-level client errors. Call `server_error_kind()` on
`ParseError` or `GvmError`; the original numeric status and message remain
available in `ServerError` or `Server`.

Explicit status 401 and 403 responses classify as authentication and permission
failures. gvmd also emits those outcomes under status 400, so exact normalized
`Authentication failed` and `Permission denied` status text receives the same
classification. Other status 400 responses remain `InvalidInput`; unrelated
statuses are `Unknown`. The classifier deliberately avoids substring guessing
and does not introduce HTTP concepts into the GMP model.

## Typed feed synchronization state

Each `Feed` now exposes `sync_state: FeedSyncState` alongside the existing raw
`currently_syncing` value. The typed view distinguishes missing data, legacy
inactive `0`, active state with an optional nested timestamp, and unsupported
direct text. Use `is_active()` and `timestamp()` without reparsing protocol
strings.

The raw field is unchanged for compatibility. With the `serde` feature, the new
field has a default so older serialized `Feed` values remain readable. Missing
or unsupported data returns `None` from `is_active()` rather than guessing.

## XML character references

Incremental and buffered XML framing now rejects signed, empty, uppercase
`#X`, non-ASCII-digit, and otherwise non-XML numeric character-reference
spellings before conversion. Valid decimal and lowercase-`#x` hexadecimal XML
references are unchanged. Applications that previously sent permissive
nonstandard spellings must emit XML-defined lexical forms.

## Supported toolchain and artifacts

The minimum supported Rust version remains 1.89. Tagged release artifacts keep
the v0.9 publication contract: five mock-server binary archives with checksums,
a Linux amd64/arm64 GHCR index, CycloneDX SBOMs and quality results, and
Sigstore provenance attestations. Only immutable `v`-prefixed tags are
published; there is no moving `latest` image.
