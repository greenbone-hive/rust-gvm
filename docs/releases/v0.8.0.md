# rust-gvm v0.8.0

rust-gvm v0.8.0 adds the complete typed asynchronous report-export lifecycle
used by current gvmd and preserves additional typed fields that v0.7 silently
dropped. It also tightens stateful mock-server fidelity and bounds retained
command history.

Callers upgrading from v0.7.0 should review the
[v0.8.0 migration guide](https://github.com/greenbone-hive/rust-gvm/blob/v0.8.0/docs/v0.8.0-migration.md).
Existing request calls remain available, but struct-literal construction of
`GetAgentSupportBundleRequest` must initialize its new `encryption` field, and
exhaustive consumers should account for the new typed projection payloads.

Highlights:

- typed queue, poll, download, and cancellation operations for scan, audit, and
  delta report exports, gated by GMP 22.7 plus positive command discovery;
- source-shaped export metadata and binary download responses;
- repeatable completed-export downloads aligned with gvmd's retention-only
  cleanup contract;
- preserved result-NVT type metadata, NVT discovery and Markdown technical
  details, and `web_application_vt` information payloads;
- forward-compatible handling of unknown future `get_info` subtypes;
- optional support-bundle encryption control with encrypted-by-default omission
  semantics;
- normalized discovered command names, stricter malformed-schedule rejection,
  correct task-tag membership filtering, and bounded mock command history;
- release binaries for five targets, each with a SHA-256 checksum;
- the Linux amd64/arm64 mock-server image at
  `ghcr.io/greenbone-hive/gvm-mock-server:v0.8.0` (no moving `latest` tag);
- CycloneDX JSON and XML SBOMs, an SBOM quality report, checksums, and Sigstore
  provenance for downloadable artifacts and the container image.

The release artifacts are built from the immutable `v0.8.0` tag and verified
against its exact qualified commit before publication completes.
