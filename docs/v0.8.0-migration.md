# Migrating from v0.7.0 to v0.8.0

`v0.8.0` extends the published v0.7 typed request surface with the complete
asynchronous report-export lifecycle and preserves additional fields emitted by
current gvmd versions. The project remains a pre-1.0 Technology Preview, so the
minor-version change is the compatibility signal.

Most v0.7 callers can upgrade without changing existing method calls. Callers
that construct public response/request structs with literals or exhaustively
match typed response enums must account for the additions below. Prefer the
provided request constructors and non-exhaustive response models.

## Asynchronous report exports

The report-export surface now models the seven-command lifecycle exposed by
current gvmd:

- `export_scan_report`;
- `export_audit_report`;
- `export_delta_scan_report`;
- `export_delta_audit_report`;
- `get_report_exports`;
- `download_report_export`;
- `cancel_report_export`.

Each command has a complete request type, associated typed response, and
request-by-value `GmpClient`/`GmpVersioned` helper. The commands require GMP
22.7 or newer and positive XML-help discovery because the negotiated protocol
version alone does not prove that a server implements them.

```rust,no_run
use gvm_client::GmpClient;
use gvm_connection::GvmConnection;
use gvm_gmp::commands::reports::{
    DownloadReportExportRequest, ExportScanReportRequest,
    GetReportExportsRequest,
};
use gvm_gmp::EntityId;

async fn export_report<C: GvmConnection + Send>(
    client: &mut GmpClient<C>,
    report_id: EntityId,
) -> Result<Vec<u8>, gvm_client::GvmError> {
    client.discover_commands().await?;

    let queued = client
        .export_scan_report(ExportScanReportRequest::new(report_id))
        .await?;
    let export_id = queued.id;

    let status = client
        .get_report_exports(GetReportExportsRequest::new(export_id.clone()))
        .await?;
    if status.items.first().map(|item| item.status.as_str()) != Some("done") {
        return Ok(Vec::new());
    }

    let downloaded = client
        .download_report_export(DownloadReportExportRequest::new(export_id))
        .await?;
    Ok(downloaded.report_export.bytes)
}
```

The download response contains decoded bytes plus export metadata. Cancellation
is intended for pending or running exports; terminal export retention remains
server-owned. See
[report-export lifecycle evidence](report-export-lifecycle-gvmd-evidence.md)
for the audited gvmd contract and version gates.

## Preserved gvmd projections

The typed response layer now retains fields that v0.7 ignored:

- `ResultNvt::type_metadata`;
- NVT `discovery` and Markdown `tech_info.description_md` values;
- the `web_application_vt` `get_info` subtype, including references and raw
  type metadata;
- unknown future `get_info` subtype names without rejecting the response.

`GenericInfo::payload` exposes these details through `GenericInfoPayload`.
Because the enum is non-exhaustive, downstream matches should keep a wildcard
arm. The new response structs are also non-exhaustive.

## Agent support-bundle encryption

`GetAgentSupportBundleRequest` gains `encryption: Option<bool>`. Its
constructor leaves the field as `None`, preserving gvmd's encrypted-by-default
omission behavior. Set `Some(false)` only when an unencrypted bundle is
explicitly required:

```rust
use gvm_gmp::commands::agents::GetAgentSupportBundleRequest;
use gvm_gmp::EntityId;

let mut request = GetAgentSupportBundleRequest::new(
    EntityId::new("agent-id").expect("valid agent ID"),
    Some(14),
);
request.encryption = Some(false);
```

Code that previously built `GetAgentSupportBundleRequest` with a struct literal
must initialize the new field or switch to `new`.

## Mock-server behavior

The stateful mock server implements the asynchronous export lifecycle and
normalizes discovered command names for capability checks. Its command history
is bounded to 1,024 entries or 16 MiB of raw XML, exposes retained/dropped
statistics, rejects malformed UTC schedule dates, and resolves task-tag filters
by tag membership.

These changes improve test fidelity. Tests that assumed unbounded history
should assert through `command_history_stats()` or drain history before the
configured limits.

Completed exports remain available after a successful download. Tests can
repeat the same download and observe the retained `done:completed` resource;
eventual deletion is gvmd retention policy, not a download side effect.

## Supported toolchain and artifacts

The minimum supported Rust version remains 1.89. Tagged release artifacts keep
the v0.7 publication contract: five mock-server binary archives with checksums,
a Linux amd64/arm64 GHCR index, CycloneDX SBOMs and quality results, and
Sigstore provenance attestations. Only immutable `v`-prefixed tags are
published; there is no moving `latest` image.
